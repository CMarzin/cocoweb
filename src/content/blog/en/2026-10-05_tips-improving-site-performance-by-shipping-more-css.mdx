<AnchorSection emoji="⚡" id="improving-site-performance-by-shipping-more-css" text="Improving site performance by shipping more CSS" url="https://github.blog/engineering/architecture-optimization/improving-site-performance-by-shipping-more-css/" />

<p class="mt-2">
Github moved from css-in-js to CSS modules and CSS variables with ~22% less time passed in the server-rendering. CSS-in-JS is a cool technology but with modern CSS you can do a lot nowedays. With the IA becoming more advanced and more fast, we now can develop and ship more « native » code, we don’t have to use so much layers which harm performance and is why we need a macbook pro with 16Gb of Ram to just visit a simple website in 2026.
</p>

<AnchorSection componentClass="mt-2" emoji="🤔" id="ship-fast-is-dead.-think-slow" text='"Ship fast" is dead. The new rule is "Think slow".' url="https://thomas-sanlis.com/p/ship-fast-is-dead-the-new-rule-is-think-slow" />

<p class="mt-2">
Very good advice from Thomas, in a sea of slop you can be the lighthouse. Don’t push 50 half finished slop project, try to solve one problem really really well and build from it.
</p>

<AnchorSection componentClass="mt-2" emoji="🗝️" id="introducing-clef" text="Introducing Clef" url="https://blog.cloudflare.com/clef-decision-models/" />

<p class="mt-2">
Clef the open-source concurrent of Jev which is only two weeks old lol.

<AnchorSection componentClass="mt-2" emoji="🍾" id="fixing-the-pr-bottlenecks" text="Fixing the PR bottlenecks" url="https://www.youtube.com/watch?v=LlgiOCmFG_w" />

<p class="mt-2">
Write more automated tests but good ones, use linter, type checker. Design your codebase in a way where you expose a small interface which is easily testable instead of testing every use case and line of your codebase.
</p>
